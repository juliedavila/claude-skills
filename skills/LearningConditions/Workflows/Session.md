# Session — set up the conditions so encoding actually happens

**Gate:** the session has a stated target, a stopping rule defined before it starts, and a
first-five-minutes action that is generative rather than receptive.

This workflow sets up conditions. It does not teach technique; once the session is running and
the work is learning a specific thing to conviction, that is `Internalize`'s job.

## Steps

### 1. Name the target as a capability, not a quantity

"Read chapter four" and "study for two hours" are quantities, and quantities are satisfied by
drift. State instead what you will be able to *do* at the end: explain a mechanism unaided,
decide between two approaches, spot the failure case.

A target you can satisfy without thinking is a target that will eventually be satisfied without
thinking.

### 2. Open generatively, in the first five minutes

Start by producing, not consuming. Before reading, write down what you expect to be true, or
attempt the question cold, or state what you already believe about the topic and where you think
it is shaky.

Guessing at material you have not learned yet genuinely helps, and this is one of the better
supported and more counterintuitive findings available. Two real qualifiers: a near-miss beats a
wild guess, so guess from whatever partial structure you have rather than at random, and at least
one well-powered study found nothing, so treat this as a good default rather than a certainty.

### 3. Size the block to the worst realistic case

Use the block length that survives a bad day, which is usually shorter than the one that sounds
serious. An unfinished long block reads as failure; a finished short one reads as a streak, and
the streak is what the practice runs on.

### 4. Set the stopping rule before starting

Decide now what ends the session, and make at least one condition about quality rather than time:

- The target capability is demonstrable cold.
- Felt effort has dropped to comfortable, which means encoding has stopped. Stop and change
  something rather than continuing.
- Load has gone past the point where you are re-reading without gain. Stop, organise what you
  have, resume later.

A session with no stopping rule ends when you get tired, and tired is when drift is most likely
and least visible.

### 5. Use felt effort asymmetrically, and hold the asymmetry

This is the most rigorous idea available in this area and the most commonly mangled:

> **Low felt effort reliably indicates that the studying is not working. High felt effort does
> NOT indicate that it is.**

Difficulty is necessary and not sufficient. A hard session can still be a wasted one, which is
why the stopping rule cannot be "it felt hard."

Hold this line carefully. The popular version collapses into "difficulty means it is working,"
and when that is combined with "mistakes are the accelerant" and "slow progress means you need
more pressure," the result removes every channel by which anyone could ever detect a bad method.
That combination is unfalsifiable, and it is how people grind for months on something broken.
`References/EvidenceBase.md` has the detail.

### 6. Close by naming one thing you now know you do not understand

Confusion identified is the next session's target and the cheapest possible handoff. It also
gives the session an output that drift cannot fake, because a fluent empty session produces no
specific confusions, only a vague sense that it went fine.

## Output

Target capability, opening generative action, block length, stopping rule, and the confusion
carried forward.

## Gotchas

- **Do not let the session open by reading.** Receptive openings set the register for the whole
  block, and the block rarely recovers into generative work afterward.
- **Do not confuse a long session with a serious one.** Length is the easiest variable to
  increase and the least related to outcome. If capacity is the goal, block quality matters and
  duration mostly does not.
- **"It felt productive" is not a session outcome.** Ask what specifically can now be done that
  could not be done before. If the answer is unclear, the session was probably receptive, and
  that is worth knowing before scheduling another one like it.
- **Do not stack a new session design onto an unstable practice.** If adherence is shaky, run
  `Workflows/Adherence.md` first. Session quality is a refinement, and refining something that
  is about to be abandoned is wasted work.
