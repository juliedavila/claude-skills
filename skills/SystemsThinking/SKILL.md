# SystemsThinking

Structural analysis of complex systems: the tools that show why the same problem keeps coming back and where a small change produces a large result. Treating symptoms patches the bug; fixing structure changes the feedback loop that keeps producing it. Most "debug it harder" attempts fail because they work at the event layer while the cause sits three or four layers below.

Five axioms:

1. **Behavior is generated by structure.** A recurring outcome has a structural cause, not a run of unrelated incidents.
2. **Events are visible; structure is not.** Most analysis stops at events. This skill walks down.
3. **Feedback loops are the unit.** Every persistent pattern is one of a small number of loop archetypes.
4. **High-leverage interventions are usually counterintuitive.** The obvious fix often makes it worse: policy resistance, shifting the burden, fixes that fail.
5. **You cannot optimize a part of a system, only the system.** Local optimization often degrades the whole.

## Workflows

| Workflow | Use when | Trigger phrases | File |
|---|---|---|---|
| **Iceberg** | Something keeps happening and event-level fixes have not held | "why does this keep happening", "structural cause", "iceberg" | `Workflows/Iceberg.md` |
| **CausalLoop** | Before a large intervention, or when a fix produced a new problem; map the relationships and preview second-order effects | "causal loop", "feedback loop", "map the relationships" | `Workflows/CausalLoop.md` |
| **FindArchetype** | The behavior looks familiar; match it to one of about ten canonical patterns and apply the documented intervention | "fixes that fail", "shifting the burden", "tragedy of the commons", "recognize this pattern" | `Workflows/FindArchetype.md` |
| **FindLeverage** | The structure is understood and the question is where to push | "leverage point", "where to intervene", "Meadows' 12" | `Workflows/FindLeverage.md` |
| **ConceptMap** | The entities and their relationships need laying out before any loop can be drawn | "concept map", "map the entities" | `Workflows/ConceptMap.md` |

Quick facts: the iceberg layers are Events, Patterns, Structures, Mental Models; loops are Reinforcing (amplifying) or Balancing (goal-seeking); there are about ten archetypes (`Archetypes.md`); Meadows' twelve leverage points run from parameters (weakest) to paradigm transcendence (strongest) (`LeveragePoints.md`). `Foundation.md` has the canonical definitions.

Pair with **RootCauseAnalysis** for incidents (it covers the event and pattern layers; this skill continues to structure and mental models) and with **FirstPrinciples** to decompose to axioms before mapping how they interconnect. This skill describes structure; it does not generate interventions, so follow it with whatever ideation skill is available.

## Examples

**Recurring incidents, Iceberg**
```
"we keep getting paged for the same class of timeout"
Events: 6 pages in 3 weeks
Patterns: all during deploy windows, all touching the payments service
Structure: auto-scaler cold-start latency exceeds the health-check timeout during deploys
Mental model: "deploys are safe if tests pass", but health checks are not in the test path
The fix is structural, not another retry
```

**Strategy, FindArchetype**
```
"why does adding engineers slow us down past team size 12?"
Match: Limits to Growth
Reinforcing loop: more engineers, more output, more hiring
Balancing loop: team size raises coordination cost, which lowers per-engineer output
Intervention: work on the balancing loop (the coordination mechanism), not the reinforcing one (stop hiring)
```

## Gotchas

- **Walk the iceberg before intervening.** Even a fix applied at the event layer should be made knowing the structural cause, so you know whether it will hold.
- **Draw the loops.** Causal loops are clearer as a diagram than as prose. If you cannot draw at least one loop, you have a list of components, not a system.
- **Name the archetype.** When the behavior matches one, the canonical intervention is documented; do not reinvent it.
- **Leverage order matters.** Parameters are low leverage, rules and structures are middle, paradigms are highest. Prefer higher where the cost allows.
- **Second-order effects are not optional.** Run any non-trivial intervention through at least one round of its own feedback loop before shipping it.
- **Delay is underrated.** Many failures come from the gap between action and feedback. Mark delays on the diagram.
- **Soft variables count.** Trust, morale and perceived safety are as real as latency. Do not drop them because they are hard to measure.
- **Blaming the model is the mistake.** When a loop says something uncomfortable ("the incentives are the cause"), the reflex is to reject the diagram. Sit with it.
